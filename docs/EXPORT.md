# 导出宣传视频

`ascii-full-export`（`bin/export-video.js`）把**已经转好的字符画数据**渲染成一支
**常规 mp4**：H.264 / yuv420p / AAC / faststart / BT.709 标记。观众不用装 Termux、
不用开服务、不用点色块，点开就播，直接传视频网站。

## 两步，别搞混

```
① 原片.mp4   ──[ ascii-full ]────────▶  字符画数据  meta.json + chunks/*.gz
② 字符画数据 ──[ ascii-full-export ]─▶  字符画风格视频  宣传.mp4
```

第 ② 步**不重新取色、不二次转码**。`chunks` 里的 `1B 索引 + 3B RGB` 被原样画成
像素，再按时间轴封进 mp4 —— 相对字符画数据**零损失**；信息损失只发生在第 ① 步
「源片 → 字符网格」。

所以「字符画 → 字符画风格视频」**不是**把 mp4 再喂一遍 `ascii-full`。真那样做会
二次采样压缩块、越叠越糊，只适合 3 秒彩蛋，不适合宣传主片。

> 本地那份 `meta.json + chunks/` 原样保留，仍可拖帧、换字形、叠音轨、局域网播放。
> 多一条导出通道 ≠ 工具变成那个 mp4：人家是「只有 mp4」，你是「随时能吐一个 mp4」。

## 最快上手

```sh
# 截 20 秒高光，字形模式，带声音，直接出可上传文件
ascii-full-export --out ./ascii-out --to ./宣传.mp4 \
  --from 90 --duration 20 --mode glyph --scale 2 --crf 18
```

没装全局就用 `node bin/export-video.js --out ./ascii-out --to ./宣传.mp4 ...`。

`--from` / `--duration` 是**相对产物第 0 帧**的秒数，不是原片时间轴。若转码时用了
`--from 10`，产物的第 0 帧对应原片第 10 秒；导出 `--from 5` 就是原片第 15 秒。

## 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--out DIR`（`--dir`） | **必填** | 产物目录 |
| `--to FILE`（`--file`） | **必填** | 输出 mp4 |
| `--from S` | `0` | 起始秒 |
| `--duration S` | 全片 | 导出时长 |
| `--mode glyph\|block` | `glyph` | 黑底彩色字 / 纯色块 |
| `--glyph SRC` | `auto` | `auto` / `atlas` / `font` / `dither` |
| `--scale N` | `1` | 整数放大 1~4，nearest 不插值 |
| `--font FILE` | 自动探测 | 字体渲染图集用的字体 |
| `--crf N` / `--preset NAME` | `18` / `medium` | x264 质量 / 预设 |
| `--no-audio` | 关 | 无声片 |
| `--ffmpeg P` / `--ffprobe P` | PATH | 指定二进制 |
| `--quiet` / `--help` / `--version` | — | 精简 / 帮助 / 版本 |

输出尺寸 = `W×8 × H×16 × --scale`。例 `--grid 60` 的 282×60 → `2256×960`；
`--scale 2` → `4512×1920`。每格按等宽字形 1:2 铺真实像素，`--scale` 走
`flags=neighbor`，**不会把笔画糊成软斑**。

## 字形来源：三级兜底，绝不黑屏

| `--glyph` | 行为 |
|---|---|
| `auto`（默认） | 产物自带 `ramp-atlas.png` → ffmpeg drawtext 按 `meta.ramp` 渲染 → 覆盖率网点 |
| `atlas` | 只用产物自带图集，缺了直接报错 |
| `font` | 只用字体渲染；`--font` 可指定字体文件 |
| `dither` | 强制 Bayer 4×4 覆盖率网点（无字体环境 / 自检用，**不是真字形**） |

- 自定义字形表（`--ramp-file`）的产物自带图集，**零字体依赖**，优先级最高。
- 内置 70 级表没有图集，用 ffmpeg `drawtext` 把每个字符写进独立 `textfile`
  再渲染成灰度图集 —— 绕开 `'` `"` `\` `:` `%` 的转义地狱。
- 每条来源都会**先验墨量**：几乎没有墨量就判为不可用并降级，日志明确写
  `⚠ 字形图集不可用 → 已降级为覆盖率网点`。不会静默产出全黑视频。
- `fontcolor=white` + 黑底，像素 = `RGB × 墨量`。索引越大字形越满 → 越亮，
  与转码端 `rampIdx(lum)` 的语义一致。

`--half`（7B/cell 上下双色）也支持：上下半格各用自己的 RGB。

## 声音

默认把 `meta.audio.tracks[]` 全部按各自的 `gain` / `offset` 混成**一条 AAC 192k**：
`atrim` 裁到导出区间 → `volume` → `adelay` → `amix(normalize=0)`。宣传平台只认
单轨，所以多轨必须在这里合并；播放器里的逐轨调节仍只作用于本地产物，互不影响。

无 `meta.audio` 或加了 `--no-audio` → `-an` 无声片。

## 为什么是这些编码参数

| 项 | 值 | 原因 |
|---|---|---|
| 视频 | H.264 / `yuv420p` | 视频网站、手机、电视、老浏览器通吃 |
| 音频 | AAC 192k / 48kHz / 2ch | 平台最稳妥的音频组合 |
| 标记 | BT.709 | `chunks` 里的 3 字节是 sRGB 语义数值；统一标 709 保证各端一致 |
| 封装 | `+faststart` | moov 前置，网页能边下边播 |
| 帧率 | `meta.fps`，`-vsync cfr` | 不补帧、不丢帧，与产物逐帧对齐 |

`meta.color.gamut = p3` 是**声明式**旁路，不改变那 3 个字节；导出统一按 BT.709
输出，不会凭空变艳。想真做 HDR/P3 交付得另走一条调色管线，不在本命令范围。

> H800 这类计算卡没有 NVENC 编码单元：`libx264` 走 CPU 是正常的。想让卡发力，
> 在导出前用 TensorRT 滤镜做超分 / 降噪，编码这一跳仍回 CPU。

## 体积与耗时

只读覆盖到的 gzip 块 —— 截 20 秒大约只读十来块，**不必把几 GB 的 chunks 全铺开**。
这正是分块按需那套设计连导出都吃到的红利。

输出体积由 `--crf` / 画面复杂度 / `--scale` 决定，与原始 chunks 体积无关：
字符画大面积黑底、颜色成块，H.264 压得动，20 秒 1080p 档通常几十 MB 量级。
CPU 开销主要花在「逐格铺像素」与 x264 编码，`--preset medium` 是平衡点。

## 排错速查

| 现象 | 处理 |
|---|---|
| 画面全黑 | 不该发生；真遇到先看日志「字形来源」是否降级成功，或加 `--mode block` 二分 |
| 看不到笔画、只有颗粒 | 走了 `dither` 降级。装字体或加 `--font <字体文件>`，再试 `--glyph font` |
| 字挤在一起 / 缺字 | 字体不含该字符；自定义表用 `--ramp-file` 生成时选覆盖全的 CJK 字体 |
| 音画不齐 | 检查各轨 `offset`；导出区间用 `--from/--duration` 统一裁，别只截画面 |
| 文件太大 | `--crf 23`、`--scale 1`、`--duration` 缩短 |
| ffmpeg 报 drawtext 缺字体 | `--font` 显式给一个存在的 `.ttf/.ttc` |

## 边界（实话）

- 导出是**快照**，不是新的可交互产物：mp4 里不能拖到任意字符密度、不能切换
  字形 / 色块、不能单独挂音轨。这些能力只在本地 `chunks` 那份里。
- 不重编码源片、不取色、不插帧；源片是什么样，字符画数据就是什么样，导出只负责
  把它拍扁成像素。
- 想做「字符叠字符」的套娃彩蛋，把导出的 mp4 当源片再跑一次 `ascii-full` 即可，
  但会二次采样压缩块，只建议几秒，别当宣传主片。
